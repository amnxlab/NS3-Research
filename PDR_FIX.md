# PDR Calculation Fix

## Problem

PDR values were **over 100%** (e.g., 127%, 243%, 142%) which is impossible.

### Root Cause

```cpp
// WRONG CODE:
int sinkRecvPkts = sinkDev->GetRouting()->SendUpPktCount();
```

**Issue:** `SendUpPktCount()` counts ALL packets sent up to higher layers, including:
- ✅ Packets where sink is the destination
- ❌ Packets the sink is **forwarding** for other nodes

This caused the sink to count forwarded packets as received packets.

### Example of Wrong Calculation

```
Sender sent: 202 packets
Sink received (destination): 50 packets
Sink forwarded (for others): 207 packets
-------------------------------------------------
SendUpPktCount() = 50 + 207 = 257  ❌ WRONG!
PDR = 257/202 = 127%  ❌ IMPOSSIBLE!
```

---

## Solution

```cpp
// CORRECT CODE:
int sinkRecvPkts = sinkDev->GetRouting()->RecvPktCount();
```

**Fix:** `RecvPktCount()` counts ONLY packets where the sink is the **final destination**.

### Corrected Calculation

```
Sender sent: 202 packets
Sink received (destination): 50 packets
-------------------------------------------------
RecvPktCount() = 50  ✅ CORRECT!
PDR = 50/202 = 24.8%  ✅ VALID!
```

---

## Aqua-Sim Counter Types

| Counter | What it Counts | Use For |
|---------|---------------|---------|
| `TotalSentPkts()` | Packets generated by THIS node | Sender's sent count ✅ |
| `RecvPktCount()` | Packets where THIS node is destination | Sink's received count ✅ |
| `SendUpPktCount()` | All packets sent to upper layer | **DON'T USE** for PDR ❌ |
| `ForwardedPktCount()` | Packets forwarded/relayed | Forwarding overhead |

## Why This Happened

In Aqua-Sim routing protocols (VBF, DBR):
- Nodes can be **both** forwarders and destinations
- `SendUpPktCount()` increments for BOTH cases:
  1. When node is destination → Send to application
  2. When node forwards → Send up for re-routing decision

This is correct for Aqua-Sim's internal logic, but **wrong for PDR calculation**.
